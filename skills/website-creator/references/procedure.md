## P01

### Separate references for composition, color, and motion

A visual direction Codex can translate into an original page.

Procedure:

1. Search Pinterest by subject and page type; search Awwwards or Dribbble for the interaction you need. Follow the reference to its author's page.

2. Collect a full view for proportions, a crop for detail, and successive frames for movement. Record the specific property to take from each reference.

3. Ask Codex for an original composition with those properties and the project's content. When a CSS property is accessible on the reference website, check its value instead of estimating it from a frame.

Original Codex prompt:

> Use the first reference's wide composition, the second's contrast, and the third's motion for an original page about my product.

Source steps: [3t3TogERIdw · 0:49](https://www.youtube.com/watch?v=3t3TogERIdw&t=49s), [1Y8OlBgafdE · 5:20](https://www.youtube.com/watch?v=1Y8OlBgafdE&t=320s).

Result check: Each reference has a URL, author, and specific property; the first section implements those choices.

## P02

### From a page image to editable HTML

A page whose heading, buttons, images, and copy remain separate elements.

Procedure:

1. Supply the desired composition and identify its background, object, heading, navigation, cards, and primary action.

2. Build the opening section with HTML/CSS or project components. Generate the product image separately; keep text and controls in the document.

3. Open the page at the reference's viewport width, compare proportions, and correct the structure before adding animation.

Original Codex prompt:

> Turn this reference into an editable HTML section. Preserve its hierarchy and adapt the content to my project.

Source steps: [3t3TogERIdw · 5:28](https://www.youtube.com/watch?v=3t3TogERIdw&t=328s), [mFgRGSOGNPM · 8:43](https://www.youtube.com/watch?v=mFgRGSOGNPM&t=523s).

Result check: Text is selectable, buttons work, and the object retains the intended crop.

## P03

### An anchor screen to consolidate the visual system

A resolved representative screen guides subsequent application pages.

Procedure:

1. Choose a representative screen and extract typography, colors, spacing, and controls from the reference.

2. Build that page in the project. Compare theme and layout variants using the same content.

3. Store the selected values in existing style files and apply them to later screens. The tutorial uses Paper; Codex can compare local variants in the browser.

Source steps: [H1l66NhU-_8 · 3:21](https://www.youtube.com/watch?v=H1l66NhU-_8&t=201s).

Result check: Variants support the same action; later screens reuse the consolidated values.

## P04

### Local documents instead of Stage preparation

Goals, references, style, and the visitor journey are available to Codex.

Procedure:

1. Write the goal, audience, required content, and primary action in local project documents.

2. Collect visual references and describe the visual system and visitor journey.

3. Give Codex those documents and the selected recipe before building. The original Stage preparation becomes readable local files.

Stage offers a 14-day trial; local documents provide a lasting free preparation route.

Source steps: [8GfWKFyAaW4 · 3:10](https://www.youtube.com/watch?v=8GfWKFyAaW4&t=190s).

Result check: Codex can identify the reference guiding each section before building it.

## P05

### Combine two visual systems in an original composition

A coherent page uses selected qualities from two references.

Procedure:

1. Choose what to take from each reference: typography, palette, structure, or a particular interaction.

2. Specify which reference governs buttons, icons, and spacing; resolve conflicting choices explicitly.

3. Apply the combination to one anchor screen with real content and review it before extending the website.

Source steps: [_SVU3oC4JX8 · 3:54](https://www.youtube.com/watch?v=_SVU3oC4JX8&t=234s), [VwGrXe2ricE · 1:29](https://www.youtube.com/watch?v=VwGrXe2ricE&t=89s).

Result check: The screen has one coherent visual system and each borrowed quality has an identified source.

## P06

### Compare variants for the same application task

Layout alternatives can be compared using identical content and actions.

Procedure:

1. Keep the same accounts, currencies, central summary, and available actions across variants.

2. Change grouping and visual hierarchy while preserving the information used for the task.

3. Compare the variants against the most frequent actions and carry the chosen values into the project.

Source steps: [H1l66NhU-_8 · 10:47](https://www.youtube.com/watch?v=H1l66NhU-_8&t=647s).

Result check: The selected layout makes the real task easier while retaining the same data and controls.

## P07

### Name the control and annotate the exact state

Codex receives a precise component name and a localized correction.

Procedure:

1. Use NameThatUI to identify the element and its interaction rules.

2. Capture the actual page state and describe the visible defect; use text annotations or Agentation when already available.

3. Request a correction to the relevant component and compare the same state after the change.

Source steps: [Jhx7n9uAKHg · 5:24](https://www.youtube.com/watch?v=Jhx7n9uAKHg&t=324s), [Jhx7n9uAKHg · 6:23](https://www.youtube.com/watch?v=Jhx7n9uAKHg&t=383s).

## P08

### Typography and icons from a coherent family

Headings, body copy, and icons share defined roles and proportions.

Procedure:

1. Assign typography roles and try actual heading lengths rather than sample copy.

2. Choose licensed fonts: Google Fonts is documented; check individual licenses on Fontshare or Fontesk.

3. Use one icon family with consistent stroke or fill and sizes. Load authorized SVGs and only the font weights needed.

Source steps: [_SVU3oC4JX8 · 2:45](https://www.youtube.com/watch?v=_SVU3oC4JX8&t=165s), [_SVU3oC4JX8 · 8:28](https://www.youtube.com/watch?v=_SVU3oC4JX8&t=508s), [SAxKK5fbjbc · 3:39](https://www.youtube.com/watch?v=SAxKK5fbjbc&t=219s).

Result check: Actual content fits the layout and the chosen fonts and icons have retained licenses.

## P11

### An interactive hero that demonstrates the product

The opening section lets visitors understand one defining operation through a small working demonstration.

Procedure:

1. Choose an actual product operation that can be demonstrated locally with public-safe inputs. Identify its real calculation or state transition.

2. Reuse that operation and the project's components in a constrained demo, such as a spacing-scale generator that changes a preview card.

3. Show inputs, output, and the relationship between them. Provide meaningful default data and labeled keyboard-accessible controls.

4. Keep any comparison mode explicit and reproducible. If the example contrasts two configurations, use fixed understandable comparison values.

5. Carry relevant visual tokens into supporting sections. Tie motion to actual demo changes and provide a usable static/reduced-motion presentation.

Original Codex prompt:

> Build a small hero demo of this product's defining operation using existing logic and components. Show cause and result, use labeled controls, and verify real output, mobile layout, and reduced motion.

Source steps: [DBJoepxxQdg · 5:14](https://www.youtube.com/watch?v=DBJoepxxQdg&t=314s), [DBJoepxxQdg · 5:27](https://www.youtube.com/watch?v=DBJoepxxQdg&t=327s), [DBJoepxxQdg · 6:12](https://www.youtube.com/watch?v=DBJoepxxQdg&t=372s), [DBJoepxxQdg · 6:47](https://www.youtube.com/watch?v=DBJoepxxQdg&t=407s).

Result check: Operate the demo with keyboard and pointer, verify the output against the real operation, and inspect mobile/reduced-motion views. The visitor can identify what the product does.

## P12

### An album-driven landing page with a shared accent palette

Selecting an authorized album cover updates a coherent record-player composition and the page's visual accent.

Procedure:

1. Prepare authorized covers, labels, and any audio the product is allowed to play. Choose an initial cover and an accent that fits it.

2. Compose a record-player visual beside live text and a clearly labeled cover selector. Use CSS/SVG or the existing renderer for the visual.

3. Store the selected cover and its palette in one state boundary. Apply derived accent tokens consistently to the intended controls and decorative details.

4. Verify foreground contrast and focus in each palette. Connect playback feedback to actual playback if audio is implemented; label decorative equalizer motion as decoration.

5. Use the same chosen content and visual direction through the record gallery and closing section. Keep factual quotes, prices, and catalog information accurate.

Original Codex prompt:

> Create a record-inspired landing composition with authorized covers and a shared selected-cover palette. Keep live text readable across palettes and connect playback controls only to actual playback.

Source steps: [DBJoepxxQdg · 7:24](https://www.youtube.com/watch?v=DBJoepxxQdg&t=444s), [DBJoepxxQdg · 8:27](https://www.youtube.com/watch?v=DBJoepxxQdg&t=507s), [DBJoepxxQdg · 8:45](https://www.youtube.com/watch?v=DBJoepxxQdg&t=525s).

Result check: Select each cover with keyboard and touch, inspect narrow layouts, and test optional playback and reduced motion. Selection, accents, and real playback state agree.
