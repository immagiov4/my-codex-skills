## Curate and make usable

Compare each candidate with the existing collection. Keep it when it fills a practical gap, materially improves a method, corrects a factual claim, or replaces a weaker resource. Merge duplicates, update existing entries, and remove superseded guidance while preserving attribution and still-useful techniques. Growth follows distinct usefulness; each run can legitimately produce no changes. A new category earns a reference file only when the existing structure cannot hold it clearly.

For an adopted technique, capture the original URL, author, publication date when available, observation date, and the relevant timestamp or component page. Explain the visible result, suitable use, implementation steps for Codex, required libraries or assets, and the check that proves the effect works on desktop, mobile, keyboard, and reduced-motion paths as applicable. Inspect the relevant video passage for motion; transcripts and search snippets alone establish textual evidence. Label adaptations and combinations as this collection's work.

Verify access, dependencies, and licensing on official documentation or repositories. Distinguish a free preview from usable free code and identify paid requirements. Keep linked source material and short original summaries; publish third-party media or code only under applicable reuse permission. Report the actual evidence inspected and leave historical observation dates intact unless that fact was rechecked.

## Validate and publish

Read repository instructions and inspect local changes and current remote revisions first. Reconcile changes without overwriting unrelated work. The maintainer authorizes routine commits and pushes limited to this skill, its attribution, and required collection discovery metadata. Use the repository's established publication path; stop for a conflict or a broader design decision rather than forcing an update. Check all local Markdown links, metadata, JSON, affected recipe cross-references, and any changed executable helper; run the available skill validator. Inspect the final diff for private material and unsupported claims.

After successful publication, reconcile changed skill files with the installed copy when running on the maintainer's machine. Preserve intentional local differences; report a synchronization conflict instead of replacing them. Use Git history for changes rather than accumulating dated update documents inside the skill.

A complete refresh exercises discovery, candidate comparison, primary-source checks, integration of useful findings, validation, publication, and installed-copy reconciliation. Record which sources and outputs were actually inspected and distinguish source-specific gaps from failure of the whole run. An unchanged collection can complete this cycle with a documented no-change decision. Browser availability in an interactive run does not prove that a later unattended run can access the same session: check the browser connection and login state on each run.

Return a concise Italian account of meaningful additions, replacements, corrections, removals, the publication link, and consequential access or verification gaps. Stay quiet when the collection is unchanged and there is no required user action.
